# টেস্টিং (Testing)

## ইউনিট টেস্ট (CI-তে চলে)

`app/src/test` — প্রতিটি পুশে GitHub Actions-এ `./gradlew testDebugUnitTest` চালানো হয়।

- অর্থ ও বাংলা সংখ্যা: `MoneyTest`, `BengaliNumberTest` — পয়সা পার্স/ফরম্যাট (লক্ষ গ্রুপিং), পরিমাণ (milli), শতকরা (bp)।
- ঋণের গণিত: `LoanMathTest` — EMI, ফ্ল্যাট/স্থির-কিস্তি স্কিডিউল, শেষ কিস্তিতে রাউন্ডিং শোষণ, সরল সুদ।
- হিসাবের দৃশ্য: `AccountingScenarioTest`, `InstallmentAllocatorTest` — পোস্টিং আকারের অখণ্ডতা, প্রাচীনতম-আগে বরাদ্দ (সুদ→ফি→আসল), অতিরিক্ত আসলে স্কিডিউল সংকোচন।
- নিরাপত্তা/ব্যাকআপ: `CryptoTest` (PBKDF2/AES-GCM রাউন্ড-ট্রিপ, ভুল পাসওয়ার্ড ব্যর্থতা), লকআউট নীতি।
- CSV: এস্কেপিং ও ফর্মুলা-ইনজেকশন সুরক্ষা।

## ইনস্ট্রুমেন্টেড টেস্ট (ডিভাইস/এমুলেটরে)

`app/src/androidTest`:

- `LedgerFlowInstrumentedTest` — আসল Room ডেটাবেসে (ইন-মেমরি) প্রোডাকশন রিপোজিটরি দিয়ে পূর্ণ প্রবাহ: আয়/খরচ/ট্রান্সফার নিরপেক্ষতা, দোকানের বাকি দ্বিগুণ না-গণনা, ঋণের দায় শুধুই আসল, ট্রায়াল ব্যালান্স শূন্য।
- `PinPadUiTest` — Compose UI টেস্ট: বাংলা সংখ্যার পিন-প্যাড সঠিক সংখ্যা ও ব্যাকস্পেস পাঠায়।

চালানোর নিয়ম (ডিভাইস/এমুলেটর সংযুক্ত থাকতে হবে):

```bash
./gradlew connectedDebugAndroidTest
```

CI-তে এমুলেটর নেই, তাই সেখানে এই টেস্টগুলো **শুধু কম্পাইল** যাচাই হয় (`assembleDebugAndroidTest`) — চালানো হয় না। বাস্তব ডিভাইসে চালিয়ে ফল যাচাই করা বাকি — এটি পরিচিত সীমাবদ্ধতা।

## হাতে-কলমে যাচাই তালিকা (প্রকাশের আগে সুপারিশ)

1. তাজা ইনস্টল → পিন সেটআপ → ভুল পিনে লকআউট বার্তা → সঠিক পিনে খুলে যাওয়া।
2. অ্যাকাউন্ট তৈরি (শুরুর ব্যালান্সসহ) → আয়/খরচ/ট্রান্সফার → ড্যাশবোর্ডে মিল যাচাই।
3. আইটেমসহ খরচ (১.৫ কেজি × দাম) → মোট ঠিক আছে কিনা।
4. দোকানে বাকি কেনা → আংশিক পরিশোধ → দোকানের খতিয়ান ও ক্যাশ মিল।
5. এনজিও ঋণ তৈরি (হাতে কম পাওয়া) → কিস্তি পরিশোধ → আসল বাকি ও সুদ খরচ।
6. ব্যক্তিকে ধার দেওয়া → আংশিক ফেরত → পাওনা বাকি।
7. সঞ্চয়ে জমা/উত্তোলন → আয়-খরচে প্রভাব নেই যাচাই।
8. এনক্রিপ্টেড ব্যাকআপ → অ্যাপ ডেটা মুছে রিস্টোর → সব হিসাব আগের মতো।
9. CSV/PDF এক্সপোর্ট ফাইল খুলে দেখা।
10. রিমাইন্ডার নোটিফিকেশন (Android 13+ অনুমতিসহ/ছাড়া)।
